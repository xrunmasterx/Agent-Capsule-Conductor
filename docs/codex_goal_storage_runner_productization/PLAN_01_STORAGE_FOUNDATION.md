# Plan 01: Storage Foundation

## Objective

Create a single local storage boundary that all durable writes pass through.

The goal is to make local evidence safe enough for a product:

- no arbitrary `run_dir` deletion;
- no duplicate active run overwrite;
- atomic JSON writes;
- locked JSONL append;
- opaque evidence/artifact refs instead of path-shaped public API contracts;
- a rebuildable SQLite index for queries and leases;
- a stable on-disk marker for ACC-owned run directories.

## Problem

Current ACC has the right evidence-first architecture, but persistence is too distributed:

- API payloads can provide `run_dir`;
- runtime deletes an existing run directory before recreating it;
- JSON writes are scattered across `acc.store`, `acc.run_index`, app services, and route helpers;
- JSONL appends do not have a consistent locking contract;
- `runs/index.json` acts like a projection/cache but can be treated as durable truth;
- artifact reads expose path-like references.

This is acceptable for an internal local prototype. It is not safe for an EXE product or a future
cloud-visible runner.

## New boundary

Introduce a storage-facing module boundary. The exact module name can be chosen during
implementation, but the product boundary should look like:

```text
acc.storage or acc.store
  owns path safety, markers, atomic writes, JSONL append, SQLite index, refs, tombstones

acc.app / acc.app.runtime
  asks storage to create runs, write evidence, append events, register artifacts

acc.server
  accepts API DTOs and returns refs/projections, not internal filesystem paths

web/
  consumes run_id, evidence_ref, artifact_ref, log_ref
```

Do not let business modules call `Path.write_text`, append JSONL, or `shutil.rmtree` for durable
ACC state after this plan is implemented.

## Storage layout

Add a product-owned internal root:

```text
<workspace>/
  runs/
    <run_id>/
      .acc-run-marker.json
      run_record.json
      run_summary.json
      events.jsonl
      nodes/
      result_store/
  .acc/
    index.sqlite
    locks/
    trash/
```

The existing `workflows/`, `callables/`, and `bindings/` directories remain user-visible definition
storage and are not moved by this plan.

## Core data model

Add explicit IDs and refs:

```text
RunId          generated by ACC; never caller-provided as a path
TaskId         stable Workbench task id
SessionId      stable assistant/agent session id
EvidenceRef    opaque reference to a run evidence file or event stream
ArtifactRef    opaque reference to a registered artifact
LogRef         opaque reference to a log stream
```

`run_id` may be user-visible. `run_dir` is internal.

## Hard contracts from architecture review

These contracts close the highest-risk gaps found by reviewing the current code paths.

### Run identity and path authority

- `run_id` must match `^[A-Za-z0-9][A-Za-z0-9_.-]{0,127}$`.
- `run_id` must not contain path separators, drive prefixes, absolute paths, `.`, or `..`.
- `runs/_*` is reserved for internal stores and cannot be used as a user run id.
- `run_dir` is derived only by storage as `<project_root>/runs/<run_id>`.
- Legacy `run_dir` input is accepted only when it is exactly `runs/<safe_run_id>`.
- The same rule must apply to `/api/workflows/run-graph`,
  `/api/workflows/run-graph/submit`, and `/api/workflows/{workflow_id}/run`.
- Any request that would create runtime state under `workflows/*`, `callables/*`, arbitrary project
  paths, or absolute paths must fail before evidence is written.

### Claim-before-write

Run creation order must be:

1. Validate request, graph, workspace binding, and runner capability.
2. Claim a unique `run_id` and write `.acc-run-marker.json`.
3. Write runtime specs and initial durable run record through storage.
4. Enqueue or start execution.

Before the claim succeeds, no code should write `runs/<run_id>/*`,
`runs/_workflow_function_specs/*`, `runs/index.json`, or `.acc/index.sqlite`.

### No overwrite or implicit delete

- Runtime setup must not `rmtree(run_dir)` to prepare a run.
- A new run directory must be absent or freshly created by the current create operation.
- Terminal rerun should allocate a new `run_id` by default.
- Deletion belongs to the retention/GC API in Plan 03, not run startup.

### Marker schema

Every ACC-owned run directory must contain `.acc-run-marker.json`:

```json
{
  "schema_version": 1,
  "run_id": "run_...",
  "created_at": "2026-06-13T00:00:00Z",
  "project_root_fingerprint": "...",
  "storage_version": "storage.v1",
  "created_by": "acc"
}
```

Storage must assert that marker `run_id` matches the directory name and that the directory is under
the canonical `runs/` root. Legacy unmarked runs are read-only compatibility inputs. Migration may
add a marker only to `runs/<safe_run_id>` directories that already contain recognized run evidence
such as `run_record.json` or `run_summary.json`.

### Writer layering

- Storage owns atomic file primitives, locks, marker checks, path protection, and ref resolution.
- `FixedRunControlLedgerWriter` remains the semantic control-ledger writer, but must use storage
  primitives for atomic writes and JSONL append.
- Replace ad hoc writers in `acc.store.write_json`, `acc.run_index.write_json`,
  `workflow_io.write_core_v2_run_summary`, `run_lifecycle.write_run_summary_status`, and
  `store.control_ledger.write_run_plan`.
- `FilesystemResultStore` should reuse the same atomic writer path instead of becoming another
  durable writer.
- JSONL files such as `events.jsonl`, `plan_steps.jsonl`, `dispatches.jsonl`, `decisions.jsonl`,
  and `wakeup_queue.jsonl` require a per-file append lock.
- JSONL `sequence` values are allocated inside the lock and restored from the highest persisted
  sequence on restart. Legacy no-sequence lines are projected as legacy events, not rewritten in
  place.

### Index and ref authority

- `.acc/index.sqlite` is the query, lease, and active-run source of truth.
- `runs/index.json` is a compatibility projection only. It must not decide duplicate run ids,
  active leases, GC candidates, or retention status.
- Server DTOs should return refs, not absolute paths, by default.
- Versioned ref grammar:
  - `artifact:v1:<artifact_id>`
  - `evidence:v1:<run_id>:events`
  - `log:v1:<run_id>:<node_id>:stdout`
- Raw `path` fields are local debug/test compatibility only.
- Index rebuild must skip reserved internal directories unless there is an explicit handler for
  `_workflow_function_specs`, `_agent_sessions`, `_authoring_sessions`, or
  `_workbench_canvas_snapshots`.

## SQLite index

Use SQLite WAL as a rebuildable local index, not as the only source of run truth.

Minimum tables:

```text
runs
  run_id primary key
  workflow_id
  task_id nullable
  status
  run_dir_rel
  created_at
  started_at nullable
  ended_at nullable
  size_bytes nullable
  pinned bool
  tombstoned_at nullable

run_nodes
  run_id
  node_id
  status
  node_dir_rel
  output_ref nullable
  artifact_bundle_ref nullable

artifacts
  artifact_id primary key
  run_id
  node_id nullable
  local_ref
  sha256 nullable
  size_bytes nullable
  classification
  upload_policy
  retention_class

leases
  lease_id primary key
  kind
  owner_id
  holder
  expires_at
```

All rows must be rebuildable from local files where possible. If SQLite is deleted, `acc storage
rebuild-index` should reconstruct run/session/artifact/task projections from the filesystem.

## API changes

Prefer new APIs that accept `run_id` intent rather than `run_dir`:

```text
POST /api/workflows/run-graph/submit
  old: { graph, run_dir, workspace?, binding_path?, input? }
  new: { graph, run_id?, workspace_alias?, binding_ref?, input? }
```

Rules:

- if `run_id` is omitted, generate one;
- if `run_id` is provided, validate it as a path component, not a path;
- never accept `../`, `/`, `\`, drive letters, or absolute paths;
- never delete an existing run unless an explicit purge API is used;
- duplicate queued/active/non-terminal run IDs must return conflict;
- terminal reruns should create a new run ID by default.

Compatibility may keep the old `run_dir` field temporarily, but it should be translated only if it
matches `runs/<safe_run_id>` exactly.

## Storage operations

Provide one implementation for:

```text
create_run(run_id?, task_id?, workflow_id?) -> RunHandle
write_json_atomic(path/ref, payload, schema_version)
append_jsonl_locked(path/ref, event)
register_artifact(run_id, node_id, local_path, metadata) -> ArtifactRef
resolve_artifact_ref(artifact_ref) -> local path after permission checks
write_run_marker(run_dir)
assert_acc_run_dir(run_dir)
claim_run_lease(run_id)
release_run_lease(run_id)
rebuild_index()
```

Atomic write should use temp file, flush, fsync where practical, and replace.

JSONL append should hold a per-file or per-run lock while assigning sequence numbers and appending.

## Migration strategy

1. Add the storage service and index without changing behavior.
2. Add run markers to newly created runs.
3. Add a migration/rebuild command that scans existing `runs/`.
4. Change async Workbench submit to create/claim runs through storage.
5. Change runtime setup to refuse overwriting existing run directories.
6. Change artifact reads to prefer `ArtifactRef`; keep old path reads only as a local debugging
   compatibility endpoint.

## Acceptance criteria

- Submitting without a run ID creates `runs/<generated_run_id>`.
- Submitting duplicate queued/active run ID returns conflict.
- Submitting `run_dir` outside `runs/<id>` is rejected.
- Runtime refuses to delete a directory without `.acc-run-marker.json`.
- Existing terminal run is not overwritten by default.
- JSON writes survive simulated crash by never leaving a half-written target file.
- Concurrent JSONL append does not duplicate event sequence numbers.
- Deleting `runs/index.json` or `.acc/index.sqlite` can be repaired by rebuild.
- Artifact UI reads through artifact refs, not arbitrary project paths.

## Verification

Add hermetic tests for:

- malicious `run_dir` inputs;
- duplicate run submission;
- run marker protection;
- atomic JSON write;
- locked JSONL append;
- index rebuild;
- artifact ref resolution and rejection of direct path traversal.
- run id validation, including separators, drive prefixes, `.`, `..`, empty ids, and `runs/_*`;
- claim-before-write failure leaves no partial run directory or runtime spec;
- JSONL sequence allocation remains monotonic after restart;
- reference parser accepts only versioned `artifact:v1`, `evidence:v1`, and `log:v1` refs;
- centralized atomic writer is used by run summary, run index, control ledger, and result-store
  persistence paths.

Default verification:

```bash
uv run pytest -q
cd web
npm run test -- --run
```
